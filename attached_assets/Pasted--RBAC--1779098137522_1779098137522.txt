أضف نظام صلاحيات متكامل (RBAC) للموقع مع لوحة تحكم لإدارة المستخدمين والصلاحيات، بحيث يستطيع المدير منح أو سحب صلاحية الوصول لكل صفحة على حدة.

١) قاعدة البيانات (PostgreSQL):

- جدول users:
  id, full_name_ar, full_name_en, email, password_hash, job_title, department, profile_image, status (active/suspended/pending), last_login, created_at, updated_at, created_by.

- جدول roles:
  id, role_name_ar, role_name_en, description, is_system_role (boolean), created_at.
  • أدوار افتراضية: Super Admin، Admin، Editor، Viewer، Guest.

- جدول pages:
  id, page_key (unique مثل: dashboard, weekend, world_news, initiatives, international_days, ai_year, smart_assistant, settings), page_name_ar, page_icon, page_order, parent_section.

- جدول permissions:
  id, permission_key (view/create/edit/delete/export)، permission_name_ar.

- جدول role_permissions:
  id, role_id, page_id, permission_id.
  • علاقة many-to-many: الدور × الصفحة × نوع الصلاحية.

- جدول user_roles:
  id, user_id, role_id, assigned_by, assigned_at.

- جدول user_page_overrides:
  id, user_id, page_id, permission_id, granted (boolean), reason, expires_at.
  • للحالات الاستثنائية: منح/منع صلاحية لشخص محدد دون تغيير دوره.

- جدول activity_logs:
  id, user_id, action (login/logout/create/edit/delete/permission_change), entity_type, entity_id, ip_address, user_agent, timestamp, details (JSON).

٢) لوحة التحكم - الواجهة الرئيسية (RTL عربي، نفس design system):

تُضاف ضمن قسم Tools باسم "لوحة التحكم" وتظهر فقط لمن لديه دور Admin أو Super Admin.

تبويبات اللوحة:
- المستخدمون
- الأدوار والصلاحيات
- مصفوفة الصلاحيات
- سجل النشاطات
- إعدادات النظام

٣) تبويب "المستخدمون":

- جدول يعرض جميع المستخدمين مع: الصورة، الاسم، المسمى الوظيفي، الدور، الحالة، آخر دخول.
- بحث + فلترة بالدور والحالة.
- زر "+ إضافة مستخدم جديد" يفتح modal بحقول: الاسم، الإيميل، المسمى الوظيفي، الإدارة، الدور المبدئي، صورة شخصية.
- خيار "إرسال دعوة بالإيميل" أو "إنشاء كلمة مرور مؤقتة".
- لكل صف: أزرار تعديل، تعليق الحساب، إعادة تعيين كلمة المرور، حذف، عرض السجل.
- زر "تعديل الصلاحيات" يفتح صفحة Override المخصصة لهذا الشخص.

٤) تبويب "الأدوار والصلاحيات":

- بطاقات تعرض كل دور مع: اسمه، عدد المستخدمين فيه، ملخص صلاحياته، أزرار تعديل وحذف.
- زر "+ إنشاء دور جديد" يسمح ببناء دور مخصص.
- عند الإنشاء/التعديل: شجرة Tree View تعرض كل الصفحات، تحت كل صفحة checkboxes للصلاحيات الخمس (عرض/إنشاء/تعديل/حذف/تصدير).
- زر "نسخ من دور موجود" لتسريع إنشاء دور مشابه.

٥) تبويب "مصفوفة الصلاحيات" (الأهم):

- جدول كبير تفاعلي: الصفوف = المستخدمون، الأعمدة = الصفحات.
- كل خلية تعرض مستوى الصلاحية بأيقونات ملوّنة:
  • ✓ أخضر = عرض كامل
  • ✏ أزرق = عرض وتعديل
  • ★ بنفسجي = صلاحيات إدارية كاملة
  • ✗ رمادي = ممنوع
- بالنقر على أي خلية تفتح قائمة لتغيير الصلاحية فورياً.
- فلترة: بالإدارة، بالدور، بالصفحة.
- زر "تصدير المصفوفة Excel" للمراجعة الورقية.
- زر "تطبيق جماعي": اختيار عدة مستخدمين + صفحات + صلاحية وتطبيقها دفعة واحدة.

٦) تبويب "سجل النشاطات":

- Timeline زمني بكل العمليات: من فعل ماذا ومتى.
- فلترة بالمستخدم، نوع العملية، التاريخ.
- تمييز عمليات حساسة (تغيير صلاحية، حذف بيانات) بلون مختلف.
- تصدير السجل CSV.

٧) تبويب "إعدادات النظام":

- إعدادات كلمة المرور: الحد الأدنى للطول، اشتراط رموز، انتهاء صلاحية كل X يوم.
- إعدادات الجلسة: مدة بقاء الجلسة، تسجيل خروج تلقائي.
- المصادقة الثنائية 2FA: تفعيل اختياري/إلزامي.
- قائمة IPs المسموح بها (اختياري).
- إعدادات الإيميل (SMTP) للدعوات وإعادة تعيين كلمة المرور.

٨) منطق التحقق من الصلاحيات (Backend Middleware):

- في كل API endpoint وكل route للصفحات، أضف middleware يفحص:
  ١. هل المستخدم مسجّل دخول؟
  ٢. هل لديه صلاحية الوصول لهذه الصفحة عبر دوره؟
  ٣. هل توجد override تعديلية في user_page_overrides؟
  ٤. هل لديه نوع الصلاحية المطلوبة (view/create/edit/delete)؟

- منطق الأولوية: User Override > Role Permission > Default Deny.

٩) واجهة المستخدم العادي:

- في القائمة الجانبية، الصفحات غير المصرح بها لا تظهر أصلاً (وليس تظهر معطّلة).
- محاولة الوصول المباشر عبر URL لصفحة ممنوعة → صفحة 403 مع رسالة "ليس لديك صلاحية الوصول، تواصل مع المدير".
- داخل كل صفحة، الأزرار غير المسموح بها (مثل حذف لمن لديه view فقط) تختفي تلقائياً.

١٠) صلاحيات افتراضية مقترحة:

- Super Admin (أنت): كل الصلاحيات على كل الصفحات، الوحيد القادر على إدارة المسؤولين.
- Admin: كل الصلاحيات عدا إدارة Super Admins.
- Editor: عرض + إنشاء + تعديل على الصفحات المحتوائية، بدون حذف ولا إدارة مستخدمين.
- Viewer: عرض فقط لكل المحتوى.
- Guest: عرض الصفحة الرئيسية والأخبار العالمية فقط.

١١) الأمان:

- تشفير كلمات المرور بـ bcrypt (12 rounds).
- JWT للجلسات مع refresh tokens.
- Rate limiting على endpoints الحساسة (login: 5/دقيقة).
- CSRF protection.
- تسجيل كل محاولة دخول فاشلة، قفل الحساب مؤقتاً بعد ٥ محاولات.
- إرسال إيميل تنبيه عند دخول من جهاز جديد.

١٢) Secrets المطلوبة:

JWT_SECRET, SESSION_SECRET, SMTP_HOST, SMTP_USER, SMTP_PASS, SMTP_FROM.

ابدأ بـ: schema قاعدة البيانات → middleware التحقق → صفحة تسجيل الدخول → تبويب المستخدمين → تبويب الأدوار → مصفوفة الصلاحيات → سجل النشاطات → الإعدادات. بعد كل خطوة، اختبر بإنشاء ٣ مستخدمين تجريبيين بأدوار مختلفة وتأكد أن كل واحد يرى ما يخصه فقط.
